# Artemis 语音控制设计

目标：不看手机，用语音完成"唤醒 → 说任务 → 执行 → 听结果"。
唤醒、识别、播报全部在手机上离线完成；识别结果交给当前选中的大模型做一次简单纠错。

## 1. 流程（第一期，已实现）

```
[待唤醒] --"小特小特"--> 嘀 --> [听任务] --说完(静音 1.6 s)--> 离线识别 --> 大模型纠错 + 判断是否可撤回(3 s 超时)
    --可撤回(打开/查看/搜索)--> 播报"好的，<任务>" --> 执行 FlashLoop --> 播报结果 --> [待唤醒]
    --不可撤回(发送/付款/删除…)--> 播报"<任务>，确认吗？" --> [听回答]
        --"确认/好的/是的"--> 执行 --> 播报结果
        --"不用/取消/算了"--> "好，不做了"
        --其他(如"不对，是…")--> 当作补充，和原话合并后重新纠错，最多 2 次
```

- 任务里提到微信、QQ、支付宝（或执行中这些 app 到了前台）：不操作，直接返回失败（账号风控风险）。
- 纠错失败或超时：用原始识别结果，并按不可撤回处理（先确认）。
- 播报边合成边播放，第一句先出声。
- 半双工：播报时不听，播报完重开麦克风再听。
- 执行任务期间释放麦克风（被操作的 app 可能要用）。
- 当前在 Artemis 自己的界面时，先回桌面再执行（我们的界面在前台时任务会暂停）。

代码：`VoiceService`（前台服务、状态机）、`SpeechEngine`（sherpa-onnx 封装）、`TaskCorrector`（纠错）。
开关：设置 → 语音唤醒（默认关；打开时申请麦克风权限）。

## 2. 选型

统一用 **sherpa-onnx 1.13.8**（k2-fsa，Apache-2.0）。库和模型都由 `scripts/fetch-voice.sh` 下载并校验 SHA-256，
放在 git 忽略的 `app/libs/` 和 `app/src/main/assets/voice/`，**打进 APK**，不需要首次下载，也不需要自建下载服务器。

| 能力 | 模型 | 打包大小 |
|---|---|---|
| 唤醒 | `kws-zipformer-wenetspeech-3.3M-2024-01-01-mobile`（int8） | 约 4.7 MB |
| 识别 | `streaming-zipformer-small-ctc-zh-int8-2025-04-01` | 约 26 MB |
| 整句识别（语音通话） | `paraformer-zh-small-2024-03-09`（int8） | 约 78 MB，**不打包**，需要时下载 |
| 播报 | `vits-piper-zh_CN-xiao_ya-medium-int8` | 约 21 MB |
| 运行库 | onnxruntime + sherpa-onnx JNI（arm64-v8a、x86_64） | 每个 ABI 约 32 MB |

- 断句不用单独的 VAD：流式识别自带端点检测（说完后静音 1.2 s 结束；4 s 没开口算没听到；单句最长 20 s）。
- 唤醒词写在 `assets/voice/kws/keywords.txt`，格式是拼音声母 + 带调韵母：`x iǎo t è x iǎo t è @小特小特`。换词只改这一行，并避开手机自带助手的唤醒词（华为"小艺小艺"、小米"小爱同学"）：最初的"小艾小艾"会把小艺一起叫醒，小艺随即抢走麦克风。

电脑上用同一套模型和参数验证过（合成语音输入）：唤醒词命中、其他句子不误唤醒；
"打开设置，告诉我电量"识别成"打开设置告诉我店量"（纠错要处理的就是这类错误）；
单字"对"会识别错，"确认 / 好的 / 是的 / 取消 / 不对"都对，所以确认语改为"说确认开始，说取消放弃"。

## 3. 大模型纠错

- 用当前选中的 provider/model，一次短请求：不带截图、不带工具，`max_tokens` 128，3 秒超时。
- 只改同音字、错别字、断句；拿不准就原样返回；只输出句子本身。
- 超时、出错、返回为空或比原句长太多，就用原始识别结果（logcat 记一条"correction skipped"，不记内容）。

## 5. 实时语音通话（可选，联网）

设置里选了「语音通话模型」（模型服务里类型为「实时语音」的模型）后，唤醒词接通实时语音通话，否则走上面的离线流程。

- **上行文字、下行语音**：你说的话在手机上离线识别（上面的 ASR），只把文字发给模型；模型的回答用语音流式播放。最早的版本上传原始音频，需要稳定约 45 KB/s 的上传，4G 上经常跟不上，服务器判断说完也要 3～6 秒，所以改成了现在这样。
- **协议**：Qwen-Audio 实时语音协议（WebSocket，24 kHz PCM 下行），`RealtimeSocket` 自己实现，不加依赖。地址填在模型服务的「实时语音地址」里，例如阿里云百炼 `wss://<域名>/api-ws/v1/realtime`；`scripts/realtime-probe.py` 可以先在电脑上试。
- **识别**：流式小模型边听边识别，只用来判断说完、判断是不是在插话；说完后用 Paraformer small 把整句音频再识别一次（手机上每句 60～200 ms），发给模型、显示在面板上的都是这次的结果。小模型准确率不够（「乘以」写成「成以」、漏字），Paraformer 明显好；它听不出字时用小模型的结果。这个模型不打进 APK（否则安装包 105 → 176 MB）：放在本项目 GitHub 的 `voice-models-1` 发布里（原名保留，附 FunASR 模型许可），选了语音通话模型后在 Wi-Fi 下自动下载、用移动数据时在设置里点下载（`SentenceModel`）；校验 SHA-256，断了接着下，存在应用私有目录。没下载完之前通话照常，用小模型的结果；下好后下一次通话在后台加载（约 1 秒）。小模型什么都没听出的声音（噪音）不再送给大模型，免得它编出字来。
- **字幕纠错**：识别结果立刻发给语音模型（不等纠错，回答不变慢）；同时让任务模型（`CaptionFixer`）结合已安装应用的名字和上一句回答改同音字、近音字（「高的地图」→ 高德地图），约 0.4～0.7 秒后替换面板上的灰字。请求里关掉思考（`enable_thinking: false`，服务不认就去掉重发）：开着思考时 18 句里有 6 句把 400 个 token 全用在思考上，没有结果。用户已经说了下一句就不再覆盖。语音模型的提示词里也说明了输入来自语音识别，要按发音理解。日志只记是否改了和耗时。
- **判断说完**：本地 Silero VAD，停顿 0.6 秒算一句；声音降到这句话峰值的四分之一以下 0.9 秒、1.2 秒没有新字、或者超过 15 秒也算说完（防止背景人声、电视把一句话拖住）。
- **声纹（可选）**：设置里读三句话录入，保存平均的说话人向量（3D-Speaker CAM++，只存在手机上）。通话中每句超过 1 秒的话都和它比较，相似度低于 0.30 的当成别人说的，忽略；插话打断也要先通过声纹。很短的话（「好」「停」）不判断。
- **先回答，再用手机**：常识、计算直接回答；时间、电量、网络、开关、音量、亮度、存储等，每句话都附带一行 `PhoneStatus`，直接回答；天气、新闻可选联网搜索（默认关闭：开启后服务有时 17～30 秒才回答，工具结果之后尤其明显）；只有要在应用里做事、信息只在应用里、或用户点名要用某个应用，才交给智能体。首页的文字任务也一样：智能体每一轮都能看到 PhoneStatus，能直接回答就第一步 finish。
- **声音设备**：通话模式下 Android 不会自己选蓝牙，所以按顺序主动选择：蓝牙免提 / LE 耳机 → 有线或 USB 耳机 → 手机外放；所选设备的麦克风一起使用。
- **执行任务时**：面板收成顶部的小胶囊（随你的声音跳动，不拦截点击，截图时隐藏）。
- **分工**：语音模型只负责对话和派任务，看不到屏幕；操作手机仍由执行任务的模型和 FlashLoop 完成。工具：`run_phone_task`、`update_task`、`stop_task`、`task_status`。
- **任务**：一句话里的几件事合成一个任务按顺序做；任务开始前留 1.5 秒，用户接着说的话会合并进去；开始后 20 秒内的补充或更正用 `update_task` 重新开始；之后的新任务排队。结果作为系统通知交给模型念出来。
- **App 直接处理、不经过模型的话**：「停下 / 停止 / 别做了 / 取消 / 算了」立刻停止任务并清空排队；「结束对话 / 挂断 / 再见」道别后挂断；确认卡片的「可以 / 不行 / 这次都允许」由 app 匹配选项（`VoiceCall.choice`），模型不能替用户决定。涉及钱的任务在工具里直接拒绝（MoneyGuard）。
- **回答**：同一时间只有一个回答；新的回答请求等上一个说完再发（服务器不允许并发），30 秒没有动静自动放开。插话要识别出字（并通过声纹）才打断，咳嗽、关门不会打断。打断一个还没发出去的回答请求（刚接通、会话还没确认时）直接撤回，不再发出去再取消：服务器曾经不理取消，把旧回答做完花了 50 秒，下一句一直在等。
- **任务没启动**：派出任务后 10 秒内没有开始运行（启动请求丢了），通话告诉用户再说一次，不再一直等；离线流程同样处理（以前会一直等，连唤醒都不再响应）。
- **花费**：上行只有文字，很便宜；15 秒没人说话挂断，通话最长 5 分钟（执行任务的时间不算），用量计入每日 token 上限。
- **界面**：`VoiceCallPanel` 在屏幕顶部显示随音量变化的圆球、状态、双方字幕和挂断按钮；执行任务时收起，不进入截图、不挡点击。
- **测试**：`VoiceTestReceiver`（只有 adb 能发）可以不用麦克风开始通话、注入一句话、挂断，用来在模拟器上反复测。
- **日志**：只记录状态、耗时、字数和工具名，不记录说话内容。

## 6. 唤醒词

默认「小特小特」（原来是「你好阿特」：「阿」很轻常被吞掉，「你好」会变调；唤醒测试从 67% 提到 78%），设置里可以改成 3～6 个汉字。汉字按 `assets/pinyin.txt`（`scripts/make-pinyin-table.py` 用 pypinyin 生成，6763 个常用字）转成唤醒模型的拼音 token（声母 + 带调韵母）；用不了的字、其他手机助手的唤醒词会被拒绝。改完不用重启，语音服务下一次读麦克风时就换上。

## 7. Android 约束

- 前台服务类型 `microphone`，常驻通知（可在通知里停止），状态栏麦克风指示灯常亮。
- Android 14 起不能从后台启动麦克风前台服务：在设置页打开开关，或打开 app 首页时自动启动。
- 华为省电会杀后台：需要把 Artemis 设为"手动管理启动"。
- 权限：`RECORD_AUDIO`、`FOREGROUND_SERVICE_MICROPHONE`；实时语音通话还要 `MODIFY_AUDIO_SETTINGS`（通话模式和外放）。
- 离线流程：音频只在内存里处理，不落盘、不上传；只有识别出的文字会发给纠错模型。
- 实时语音通话：只把识别出的文字发给所选的模型服务，音频不上传、不落盘；声纹只保存在手机上。
