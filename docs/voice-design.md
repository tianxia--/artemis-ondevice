# Artemis 语音控制设计

目标：不看手机，用语音完成"唤醒 → 说任务 → 执行 → 听结果"。
唤醒、识别、播报全部在手机上离线完成；识别结果交给当前选中的大模型做一次简单纠错。

## 1. 流程（第一期，已实现）

```
[待唤醒] --"你好阿特"--> 嘀 --> [听任务] --说完(静音 1.6 s)--> 离线识别 --> 大模型纠错 + 判断是否可撤回(3 s 超时)
    --可撤回(打开/查看/搜索)--> 播报"好的，<任务>" --> 执行 FlashLoop --> 播报结果 --> [待唤醒]
    --不可撤回(发送/付款/删除…)--> 播报"<任务>，确认吗？" --> [听回答]
        --"确认/好的/是的"--> 执行 --> 播报结果
        --"不用/取消/算了"--> "好，不做了"
        --其他(如"不对，是…")--> 当作补充，和原话合并后重新纠错，最多 2 次
```

- 任务里提到微信、QQ、支付宝（或执行中这些 app 到了前台）：不操作，直接返回失败（账号风控风险）。
- 纠错失败或超时：用原始识别结果，并按不可撤回处理（先确认）。
- 播报边合成边播放，第一句先出声。
- 半双工：播报时不听，播报完重开麦克风再听。
- 执行任务期间释放麦克风（被操作的 app 可能要用）。
- 当前在 Artemis 自己的界面时，先回桌面再执行（我们的界面在前台时任务会暂停）。

代码：`VoiceService`（前台服务、状态机）、`SpeechEngine`（sherpa-onnx 封装）、`TaskCorrector`（纠错）。
开关：设置 → 语音唤醒（默认关；打开时申请麦克风权限）。

## 2. 选型

统一用 **sherpa-onnx 1.13.8**（k2-fsa，Apache-2.0）。库和模型都由 `scripts/fetch-voice.sh` 下载并校验 SHA-256，
放在 git 忽略的 `app/libs/` 和 `app/src/main/assets/voice/`，**打进 APK**，不需要首次下载，也不需要自建下载服务器。

| 能力 | 模型 | 打包大小 |
|---|---|---|
| 唤醒 | `kws-zipformer-wenetspeech-3.3M-2024-01-01-mobile`（int8） | 约 4.7 MB |
| 识别 | `streaming-zipformer-small-ctc-zh-int8-2025-04-01` | 约 26 MB |
| 播报 | `vits-piper-zh_CN-xiao_ya-medium-int8` | 约 21 MB |
| 运行库 | onnxruntime + sherpa-onnx JNI（arm64-v8a、x86_64） | 每个 ABI 约 32 MB |

- 断句不用单独的 VAD：流式识别自带端点检测（说完后静音 1.2 s 结束；4 s 没开口算没听到；单句最长 20 s）。
- 唤醒词写在 `assets/voice/kws/keywords.txt`，格式是拼音声母 + 带调韵母：`n ǐ h ǎo ā t è @你好阿特`。换词只改这一行，并避开手机自带助手的唤醒词（华为"小艺小艺"、小米"小爱同学"）：最初的"小艾小艾"会把小艺一起叫醒，小艺随即抢走麦克风。

电脑上用同一套模型和参数验证过（合成语音输入）：唤醒词命中、其他句子不误唤醒；
"打开设置，告诉我电量"识别成"打开设置告诉我店量"（纠错要处理的就是这类错误）；
单字"对"会识别错，"确认 / 好的 / 是的 / 取消 / 不对"都对，所以确认语改为"说确认开始，说取消放弃"。

## 3. 大模型纠错

- 用当前选中的 provider/model，一次短请求：不带截图、不带工具，`max_tokens` 128，3 秒超时。
- 只改同音字、错别字、断句；拿不准就原样返回；只输出句子本身。
- 超时、出错、返回为空或比原句长太多，就用原始识别结果（logcat 记一条"correction skipped"，不记内容）。

## 5. Android 约束

- 前台服务类型 `microphone`，常驻通知（可在通知里停止），状态栏麦克风指示灯常亮。
- Android 14 起不能从后台启动麦克风前台服务：在设置页打开开关，或打开 app 首页时自动启动。
- 华为省电会杀后台：需要把 Artemis 设为"手动管理启动"。
- 权限：`RECORD_AUDIO`、`FOREGROUND_SERVICE_MICROPHONE`。
- 音频只在内存里处理，不落盘、不上传；只有识别出的文字会发给纠错模型。
